# 考研英语工作台 · 需求与落地方案

> 版本：v1.5 ｜ 日期：2026-11-19 ｜ 状态：公开代码版；完整题库改为邮件申请、手动导入，不进入公开仓库
> 核心原则：**人类主导（需求 / 优先级 / 验收），AI 协作（生成 / 重构 / 检查）**

---

## 0. 一句话目标

做一个**手机可用、本地优先、无广告**的考研英语练习工作台：以 2007–2026 真题为学习地图，支持阅读作答判分、长按查词、生词本、使用说明、本地记忆、邮件反馈、可选的 Supabase 云同步、进度保存、错题复习与数据导入导出。

**非目标（明确不做）**

- 不做口语 / 写作批改
- 本版只做**阅读**（听力入口已移除）
- 不做整篇自动翻译；查词只针对单个单词
- 不做账号体系、社区、排行榜
- 不做服务端反馈收集；反馈通过本机邮件客户端发送
- 云同步是可选功能；不配置 Supabase 时完全本地运行
- 不做付费课程、广告、内容推荐流
- 不在仓库中提交受版权保护的全套真题原文；完整题库邮件申请后由使用者在本机导入

## 1. 需求澄清：拷问式指令

### 1.1 拷问清单（Grill Me）

| # | 拷问 | 本项目的回答 |
|---|---|---|
| 1 | 用户是谁？ | 主要是“我”：备考考研英语一/二的个人学习者 |
| 2 | 在什么设备上用？ | 手机为主（通勤/碎片时间），电脑为辅（精读） |
| 3 | 一次用多久？ | 8–25 分钟，一篇阅读或几篇短阅读 |
| 4 | 最核心的动作是什么？ | 做题 → 对答案 → 看解析 → 记录错题 |
| 5 | 必须保留什么？ | 作答记录、进度、错题、导出文件 |
| 6 | 可以砍掉什么？ | 口语、写作、账号、社交、广告、复杂图表 |
| 7 | 内容从哪来？ | 本地 `data/real-exams.json`（148 篇 / 740 题）+ 导入器；文件不进仓库 |
| 8 | 数据放哪？ | 本地优先（localStorage），可导出 JSON 备份 |
| 9 | 成功的标准是什么？ | 刷新不丢进度、手机能顺畅做完一篇、导出能还原 |
| 10 | 什么时候算“够了”？ | P0 全部通过即上线；P1 按周迭代 |

### 1.2 结构化需求

**用户故事**

- 作为考生，我想按年份筛题，这样我能按计划推进。
- 作为考生，我想做完立刻看到对错与解析，这样我能当场纠正。
- 作为考生，我想进度自动保存，这样我换页面/关浏览器也不丢。
- 作为考生，我想导出备份，这样我换设备或清缓存也不怕。
- 作为考生，我想只看错题，这样我不用重复刷已会的题。
- 作为考生，我希望每次打开都知道怎么用，并能直接续上上次进度。
- 作为考生，我想通过邮件反馈问题或建议，而不是被引导到第三方表单。
- 作为考生，我想在电脑和手机上续上同一份进度，而不是每次手动搬 JSON。
- 作为考生，我希望电脑关机后手机仍能打开应用，断网也能做题。

**范围边界**

- 内容：**仅阅读**；本地 `data/real-exams.json` 含 148 篇真题（文件不提交仓库），也支持自行粘贴/导入
- 数据：单机、本地；不做实时同步
- 交互：3 次点击内进入练习；提交后立即出分
- 视觉：简洁、留白、无广告位；支持深色与字号调节

### 1.3 成功标准（可验收）

| 维度 | 指标 | 目标 |
|---|---|---|
| 功能 | 进度保存成功率 | ≥ 99.9%（本地写入 + 导出兜底） |
| 功能 | 导入 → 作答 → 导出 → 再导入 | 100% 还原 |
| 体验 | 进入练习的点击次数 | ≤ 3 次 |
| 体验 | 手机首屏可用 | ≤ 2.5s（4G，静态托管） |
| 稳定 | 控制台报错 | 0 |
| 体验 | 使用说明自动展示 | 每次完整进站 100% 弹出，可一键关闭 |
| 记忆 | 本地记忆生成 | 首次进站 100% 生成；记录进站次数、上次篇目与进度 |
| 记忆 | 继续上次 | 点击后可回到上次篇目，已答题数不丢 |
| 反馈 | 邮件通道 | `mailto:` 收件人 100% 为 `qdgzhtao@163.com`，默认不包含文章内容 |
| 同步 | 跨设备合并 | 同一同步码的两台设备可合并进度；断网时本地功能不受影响 |
| 部署 | 电脑关机可用 | 部署到 HTTPS 静态托管后，手机不依赖电脑即可打开，PWA 可安装 |
| 内容 | 题库覆盖 | 英语一 2007–2026（80 篇）+ 英语二 2010–2026（68 篇），共 148 篇 / 740 题 |

### 1.4 原型参考（信息架构）

```
工作台（今日目标 / 统计 / 继续练习 / 20 年计划 / 最近练习）
├─ 题库（筛选 + 计划列表 + 导入）
│   └─ 练习（文章 | 题目；计时；提交；解析）
├─ 错题本（错题 + 解析 + 回本篇）

└─ 设置（主题 / 字号 / 目标 / 导入导出 / 清空）
```

参考风格：Notion 的留白 + 阅读类 App 的分栏；主色深绿（#2f6f5e），正文衬线字体。

## 3. 数据模型

### 3.1 存储键

| Key | 内容 |
|---|---|
| `ky.memory.v1` | 本地记忆：记忆编号、首次使用、最近访问、进站次数、上次篇目/进度 |
| `ky.cloud.v1` | 云同步配置：Supabase URL、Anon Key、同步码、自动同步开关、上次同步时间/错误 |
| `ky.bank.v1` | 导入的题库数组 |
| `ky.progress.v1` | `{ [paperId]: { answers, submitted, seconds, score, total, updatedAt } }` |
| `ky.settings.v1` | `{ theme, fontSize, dailyGoal, lookupOnline }` |
| `ky.vocab.v1` | 生词本数组 `{ word, pos, zh, context, paperId, createdAt, updatedAt, count }` |
| `ky.dictcache.v1` | 在线查词缓存 `{ [word]: { zh, t } }`，30 天有效 |

### 3.2 Paper

```json
{
  "id": "y2013-t3",
  "year": 2013,
  "exam": "英语一",
  "type": "reading",
  "title": "2013 英语一 Text 3",
  "subtitle": "可选",
  "passage": "段落一\n\n段落二",
  "audio": "",
  "questions": [
    {
      "id": "31",
      "stem": "题干",
      "options": [{ "label": "A", "text": "..." }],
      "answer": "B",
      "explanation": "解析"
    }
  ]
}
```

### 3.3 约束

- `id` 唯一；计划内篇目使用 `y{year}-t{n}`（英语一）与 `e2-{year}-t{n}`（英语二）
- `passage` 用空行分段
- `answer` 为 `A/B/C/D`
- 单篇建议 ≤ 8,000 字；音频用 URL，不塞 base64

## 4. 四阶段落地

### 阶段 1：需求澄清（1–2 小时）

**动作**

1. 用“拷问式”模板连续追问 10 个问题（见 1.1）。
2. 把回答固化成：一句话目标、用户故事、范围、成功标准、非目标。
3. 产出页面清单与数据结构（先定 schema，再写 UI）。
4. **冻结 P0**：本期只做 P0，P1/P2 进 backlog。

**产出物**

- 本文件第 1–3 节
- 一张信息架构图（文字版即可）

**验收**

- 能一句话说清“给谁、解决什么、不做什么”
- 每个 P0 功能都有可测试的验收标准

---

### 阶段 2：迭代开发（每轮只改 1 个核心问题）

**迭代记录（本原型真实路径）**

| 轮次 | 只改一个核心问题 | 验证方式 | 结果 |
|---|---|---|---|
| I0 | 单页壳 + 示例题库 | 打开页面能看到题库 | ✅ |
| I1 | 做题闭环（作答/判分/解析） | 手动答对答错各一次 | ✅ |
| I2 | 持久化（localStorage + 草稿） | 刷新、切页、关浏览器重开 | ✅（曾发现列表筛选 bug，已修） |
| I3 | 规模（2007–2026 计划 + 导入器） | 导入单篇/批量/备份 | ✅ |
| I4 | 复习（错题本 + 统计） | 故意做错 → 错题出现 → 回做 | ✅ |
| I5 | 体验（响应式/深色/字号/PWA） | 390px 手机 + 1440px 桌面截图 | ✅ |

**每轮固定动作**

1. 写一句“本轮只解决什么”。
2. 改代码（AI）。
3. 人工跑 5 项冒烟测试：打开、作答、提交、刷新、导出。
4. 记录“变更清单 + 未解决项”。
5. 通过后再进下一轮；**不合并两个核心改动**。

**冒烟测试清单（每次发布前）**

- [ ] 首屏无报错，数据统计正确
- [ ] 能进入一篇并作答
- [ ] 提交后分数、解析、错题正确
- [ ] 刷新后进度仍在
- [ ] 导出 JSON 能再次导入
- [ ] 390px 宽度下无横向滚动

---

### 阶段 3：部署上线（半天）

**平台对比**

| 平台 | 成本 | HTTPS | 适合 |
|---|---|---|---|
| CloudStudio / GitPod / Codespaces | 免费额度 | ✅ | 快速验证、手机预览 |
| Netlify / Vercel / Cloudflare Pages | 免费 | ✅ | 长期静态托管 |
| 自有服务器 + Nginx | 低 | 需配置 | 有域名与运维经验 |

**步骤**

1. 推送仓库（只需静态文件）。
2. 配置发布目录为仓库根目录 `.`，无需构建命令。
3. 获得 HTTPS URL。
4. 手机打开 → 浏览器菜单 → **添加到主屏幕**（PWA）。
5. 用 Lighthouse 检查：性能、可访问性、PWA。

**优化**

- 静态资源走 CDN（托管平台默认）
- 题库/进度走 localStorage，减少请求
- Service Worker 预缓存应用壳，离线可打开
- 图片/音频放对象存储，不塞进 HTML

---

### 阶段 4：长期维护（每周 30 分钟）

**监控指标**

| 类型 | 指标 | 采集方式 |
|---|---|---|
| 功能完整性 | 进度保存成功率 | 本地写入 try/catch + 导出兜底 |
| 体验 | 首屏加载 | Lighthouse / 手动秒表 |
| 稳定性 | 控制台报错 | 发布前手动检查 |
| 学习效果 | 每周完成篇数、正确率 | 应用内统计页 |

**反馈闭环**

```
使用中记录问题 → 每周挑 1 个最高频问题 → 用“拷问”补需求
→ AI 改代码 → 冒烟测试 → 发布 → 记录变更
```

**节奏建议**

- 周一：看统计，定本周唯一目标
- 周三：实现 + 自测
- 周五：发布 + 写 3 行变更记录
- 周日：导出一次备份

## 6. 风险控制与避坑

| 风险 | 表现 | 对策 |
|---|---|---|
| 功能膨胀 | 越做越多，主流程反而卡 | P0 冻结；新想法进 backlog |
| AI 堆砌 | 一次改 5 个点，问题难定位 | 每轮只改 1 个核心问题 |
| 数据丢失 | 清缓存/换设备后归零 | 每周导出；关键写入 try/catch；提供完整备份 |
| 版权 | 批量搬运真题原文 | 只做计划骨架 + 导入器；示例用原创；用户资料仅存本机 |
| 安全 | 导入的 HTML 被执行 | 所有导入内容用 `textContent`/转义渲染 |
| 性能 | 长列表 + 大文本卡顿 | 按需渲染、分页/虚拟列表、音频用 URL |
| 在线查词 | MyMemory 不可用、限流或网络中断 | 本地词库兜底；显示明确错误与重试；缓存 30 天；可关闭联网查词 |
| 隐私 | 查词请求泄露文章内容 | 只发送当前单词，不发送整篇原文；可在设置中关闭 |
| 部署 | 云 IDE 休眠/额度 | 正式使用迁到静态托管 |

## 7. 可迁移性

这套方法可平移到：博客、工具站、课程站、个人知识库。

**不变的三件事**

1. **需求精确化**：先用拷问把“想要”变成“可验收”。
2. **迭代验证**：每轮只解决一个真实问题，用数据/操作验证。
3. **部署优化**：静态优先、CDN、本地缓存、可导出。

**可替换的部分**

- 内容 schema（阅读 → 单词卡/错题/课程）
- 存储层（localStorage → IndexedDB → 可选云同步）
- 视觉主题（换 CSS 变量即可）
